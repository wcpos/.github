# Review gate installation

Repository administrators: land the central workflow and script on `wcpos/.github`'s `main`, then copy `stubs/review-gate.yml` to `.github/workflows/review-gate.yml` on each repository's default branch (needed for PR issue-comment events). The stub must grant `statuses: write`, `pull-requests: write`, and `contents: read`. For least privilege, do not add `secrets: inherit`: the reusable gate needs only `GITHUB_TOKEN`, which GitHub provides automatically. Require the **commit status context `review-gate`**, not a caller-prefixed check-run name, on every trunk using the line below; retain required thread resolution and disable bypasses. Every supported trigger evaluates the PR; when token permissions allow it, unmerged PRs publish that context on the API-reported PR head, never the issue-comment run's default-branch SHA. Merged verdicts publish no status, including no pending status. The workflow runs trusted central code, never PR code. The stub uses `pull_request`. If a fork PR token receives HTTP 403 while publishing its status, that run logs the missing status and exits zero without satisfying the required status; a repository member must dispatch `review-gate` with `pr=<number>` from the default branch. Same-repository API errors still fail the job. Codex refuses `@codex review` posted by `github-actions[bot]` (observed 2026-10-17: it replies with account-setup errors), so the gate does not post it; a repository member posts it (the local post-push hook does so on every push), and the gate's failure text says so. Resolving a thread alone does not trigger these workflows: **RESOLVE FIRST, THEN REPLY** so the reply’s `pull_request_review_comment` event sees the resolved thread, or manually dispatch the workflow with the PR number. The weekly sweep audits merged PRs only; it does not refresh open-PR statuses. Review-body dispositions require a non-bot top-level PR comment after the review's last edit (or submission if unedited). CodeRabbit’s newest review must match the head commit OID. Codex accepts a completed head-bound state, any head-bound review, or a qualifying receipt. A Codex receipt has no OID: it is accepted only after both the head commit date and the latest non-bot `@codex review` request, with a receipt-based warning; without a request it is not accepted. API failures publish failure when the head SHA and status endpoint are available; if both the API lookup and the event lack a head SHA, publication is impossible and the job fails. Sweep history cannot prove resolution time; it reports current unresolved state and surviving pre-merge comments, checking review OIDs against the PR head and receipt timestamps against the last HEAD commit and review request, not the merge commit timestamp.

Ruleset requirement shorthand (not a complete GitHub ruleset JSON document):

```yaml
required_status_checks: review-gate
```

Security notes: the reusable workflow executes only `wcpos/.github`’s own code (sparse checkout of `scripts`), never pull-request code. Pin the reusable workflow reference to a commit SHA of `wcpos/.github` rather than `@main`; the checkout uses `job.workflow_sha`, so this pin covers the script too. Update each repository’s pin when rolling out gate changes.
