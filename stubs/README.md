# Review gate installation

Repository administrators: land the central workflow and script on `wcpos/.github`'s `main`, then copy both `stubs/review-gate.yml` and `stubs/review-gate-publish.yml` to `.github/workflows/` on each repository's default branch (needed for issue-comment and publisher events). Both stubs must grant `statuses: write`, `pull-requests: write`, and `contents: read`. For least privilege, do not add `secrets: inherit`: the reusable gate needs only `GITHUB_TOKEN`, which GitHub provides automatically. Require the **commit status context `review-gate`**, not a caller-prefixed check-run name, on every trunk using the line below; retain required thread resolution and disable bypasses. Every supported trigger evaluates the PR; when token permissions allow it, unmerged PRs publish that context on the API-reported PR head, never the issue-comment run's default-branch SHA. Merged verdicts publish no status, including no pending status. The workflow runs trusted central code, never PR code. The stub uses `pull_request`. Any event-run status POST returning HTTP 403 logs a restricted token and exits zero without satisfying the required status. The second stub runs after every completed “Review gate” run, re-reads the open PRs for its head SHA, and publishes the aggregate verdict with the base repository token. This covers fork and same-repository Dependabot heads, including replacing stale successes with failures; a publisher status 403 is a hard failure. It never consumes artifacts or executes code from the triggering run. No open PRs for the SHA means no status is published. Member dispatch remains available for backfill, not restricted-token recovery. Codex refuses `@codex review` posted by `github-actions[bot]` (observed 2026-10-17: it replies with account-setup errors), so the gate does not post it; a repository member posts it (the local post-push hook does so on every push), and the gate's failure text says so. Resolving a thread alone does not trigger these workflows: **RESOLVE FIRST, THEN REPLY** so the reply’s `pull_request_review_comment` event sees the resolved thread, or manually dispatch the workflow with the PR number. Dismissed reviews are ignored, and approvals require no body reply. All reviewer-started threads require a reply by another author (bot findings require a non-bot reply); author-started threads still must be resolved. Review-body dispositions require a non-bot top-level PR comment after the review's last edit (or submission if unedited). CodeRabbit’s newest review must match the head commit OID. Freshness uses the latest of the head commit date, head force-push, and base change; reviews and Codex states must be at or after that boundary. Codex accepts a completed head-bound state, any head-bound review, or a qualifying receipt. A Codex receipt has no OID: it is accepted only after both the freshness boundary and the latest non-bot `@codex review` request, with a receipt-based warning; without a request it is not accepted. API failures publish failure when the head SHA and status endpoint are available; if both the API lookup and the event lack a head SHA, publication is impossible and the job fails.

Ruleset requirement shorthand (not a complete GitHub ruleset JSON document):

```yaml
required_status_checks: review-gate
```

Security notes: the reusable workflow executes only `wcpos/.github`’s own code (sparse checkout of `scripts`), never pull-request code. Pin both stubs’ reusable workflow references to a commit SHA of `wcpos/.github` rather than `@main`; the checkout uses `job.workflow_sha`, so each pin covers the script too. Update each repository’s pin when rolling out gate changes.

Before adding the ruleset requirement, backfill existing open PRs in each repository: `for n in $(gh pr list --state open --json number -q '.[].number'); do gh workflow run review-gate.yml -f pr=$n; done`. Unmerged workflow runs publish pending before review pagination (publisher runs first discover open PRs for the SHA), then an aggregate status for every open PR sharing that head SHA; any failing PR blocks the shared context.
